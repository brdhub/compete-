# ⚔️ 名字对战 Demo

输入名字，AI 联网搜索相关信息后生成角色与技能，再由确定性战斗引擎对战，
以手机网页的形式动态播放战斗过程。内置两种玩法：

- **⚔️ 名字对战**：输入正反两个名字，生成双方角色，自动开打分胜负。
- **🗼 试炼之塔**：输入勇者之名 + 挑战场地，连闯三层试炼。战斗为**手动选招**的
  回合制互动战斗，每通关一层可获得「三选一强化」，登顶即胜利结算（roguelike 打怪升级）。

## 战斗机制

- **回合制**：双方轮流出手，先手由攻击力决定。
- **命中 / 闪避**：攻击基本必中，闪避是小概率事件——实际命中率 =
  `100 - (100 - 标称命中) × 0.25`，并设 80% 下限，杜绝"频繁落空"的挫败感。
- **攻击技能**：造成伤害，伤害 = (技能威力 + 攻击力×0.3) × 随机浮动，再按对方防御按比例减伤。
- **防御技能**：每个角色固定带一个**主题化防御技能**。使用后进入「格挡姿态」，
  抵挡对手**下一次命中**的 `block%` 伤害，格挡用掉即消失——是否在敌人蓄力大招前格挡，
  是手动战斗的核心博弈点。

## 玩法

### ⚔️ 名字对战

1. 在手机网页上输入两个名字（真实人物、虚构角色、品牌、概念都行）
2. 后端调用 Anthropic Claude，开启 **web search** 联网搜索这两个名字
3. Claude 根据搜到的真实特征生成双方角色（血量、攻击、防御、含一个防御技能）
4. Python 战斗引擎确定性地模拟回合制对战，逐回合播放、更新血条、判定胜负

### 🗼 试炼之塔（打怪升级模式）

1. 输入**勇者之名**与**挑战场地**（如：熔岩深渊 / 霓虹赛博都市 / 武侠江湖）
2. Claude 据此一次生成主题化英雄 + **围绕场地的三层敌人**（由弱到强，各带防御技能）；
   无密钥/联网失败时本地兜底
3. 逐层**手动选招**：每回合点一个技能，后端结算我方行动 + 敌方 AI 行动并播放，
   残血时该不该用防御技能格挡敌人的大招，由你决定
4. 通关后弹出**三选一强化**（加血/加攻/加防/技能伤害/命中/护盾强化/习得新技能，分普通·稀有·史诗）
5. 选中的强化即时应用到英雄（后端统一裁剪到合法范围），带着更强的英雄挑战下一层
6. 连闯三层全部通过 → 🎉 登顶成功结算；任意一层落败 → 试炼失败，可一键再战

> 三个敌人为何在开局一次性生成：英雄与三敌人由 Claude 围绕场地一次产出，
> 避免逐层调用的多次延迟；强度随层数曲线明显递增（第 1 层热身、第 2 层强敌、
> 第 3 层压轴），每通关一层的「三选一强化」收益也随之加大，形成「升级 → 变强 →
> 挑战更强敌人」的成长闭环。手动选招后，"会不会用防御技能"让全清率从约 2%（乱点）
> 提升到约 23%（合理选招）——操作真正产生影响，最终层是名副其实的高潮而非送分关。

## 架构

```
frontend/index.html      手机端优先的单页（两种模式共用竞技场 + 血条/回合动画 + 手动选招操作栏 + 护盾表现）
backend/
  main.py                FastAPI 服务，提供 /api/battle 与 /api/adventure/*，并托管前端
  models.py              Pydantic 数据模型（角色 / 技能含攻防类型 / 回合 / 战斗状态 / 英雄 / 强化）
  character_gen.py       调用 Claude 生成对战角色或试炼英雄（固定带防御技能）；无密钥时 mock 兜底
  battle_engine.py       纯 Python 确定性战斗引擎：命中/格挡结算 apply_action（自动与手动两种模式共用）
  adventure.py           试炼之塔逻辑：按场地用 Claude 生成三层敌人（失败本地兜底）、三选一强化池、强化应用
```

**为什么把「生成」和「战斗」拆开**：让大模型一边记血量一边讲故事，
数值经常前后对不上。所以属性由 Claude 生成，战斗过程交给真实代码计算，
保证血条和每个回合的数据百分百自洽。两种模式共用同一个 `apply_action` 单步结算，
行为完全一致；后端保持无状态——英雄、敌人、战斗状态都由前端持有并在每次请求中带上。

## 运行

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

### 2.（可选）配置密钥启用联网生成

```bash
cp .env.example .env
# 编辑 .env，填入 ANTHROPIC_API_KEY
```

> 不配置密钥也能运行：会自动进入 **mock 模拟模式**，用随机属性生成角色，
> 界面和玩法完全可用，方便先看效果。

### 3. 启动服务

```bash
cd backend
uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

### 4. 访问

- 电脑浏览器：<http://localhost:8000>
- 手机浏览器：与电脑同一 Wi-Fi 下访问 `http://<电脑局域网IP>:8000`
  （查看 IP：Windows 用 `ipconfig`，macOS/Linux 用 `ifconfig` / `ip addr`）

## 接口

`POST /api/battle`

请求：

```json
{ "side_a": "孙悟空", "side_b": "奥特曼" }
```

响应（节选）：

```json
{
  "character_a": { "name": "孙悟空", "max_hp": 200, "skills": [...] },
  "character_b": { "name": "奥特曼", "max_hp": 210, "skills": [...] },
  "events": [
    { "turn": 1, "actor": "孙悟空", "skill": "如意金箍棒", "damage": 32, "target_hp_after": 178, "narration": "..." }
  ],
  "winner": "孙悟空",
  "source": "claude"
}
```

`source` 为 `claude` 表示联网生成，`mock` 表示未配置密钥的模拟模式。

### 试炼之塔接口

后端保持无状态：英雄、敌人、战斗状态都由前端持有，并在每次请求中带上。

`POST /api/adventure/start` — 生成英雄 + 按场地生成三层敌人

```json
// 请求
{ "name": "孙悟空", "arena": "熔岩深渊" }
// 响应（节选）
{
  "hero": { "name": "孙悟空", "max_hp": 165, "skills": [ ... 含一个 kind=defense 的防御技能 ] },
  "enemies": [
    { "name": "焰鳞熔蜥", "max_hp": 105, "skills": [...] },
    { "name": "炽魂炎魔", "max_hp": 182, "skills": [...] },
    { "name": "涅槃焚世龙皇", "max_hp": 286, "skills": [...] }
  ],
  "arena": "熔岩深渊",
  "intro": "...",
  "source": "claude"
}
```

`POST /api/adventure/turn` — 手动选招的单回合结算（我方行动 + 敌方 AI 行动）

```json
// 请求
{
  "hero": { ... }, "enemy": { ... },
  "state": { "hero_hp": 165, "enemy_hp": 105, "hero_block": 0, "enemy_block": 0, "turn": 0 },
  "skill_index": 0
}
// 响应（节选）
{
  "events": [
    { "actor": "孙悟空", "kind": "attack", "hit": true, "damage": 31, "blocked": 0, "target_hp_after": 74, "narration": "..." },
    { "actor": "焰鳞熔蜥", "kind": "defense", "block": 46, "target_hp_after": -1, "narration": "...摆出格挡姿态..." }
  ],
  "state": { "hero_hp": 165, "enemy_hp": 74, "hero_block": 0, "enemy_block": 46, "turn": 2 },
  "battle_over": false,
  "winner": ""
}
```

事件 `kind=defense` 表示进入格挡姿态（`block` 为减伤%、`target_hp_after=-1` 即血量不变）；
`kind=attack` 时 `blocked` 为被对手格挡卸去的伤害量。

`POST /api/adventure/upgrades` — 通关一层后抽取三选一强化

```json
// 请求
{ "hero": { ... } }
// 响应
{ "upgrades": [ { "id": "might", "name": "狂暴之力", "rarity": "common", "add_attack": 6 }, ... ] }
```

`POST /api/adventure/upgrade` — 把选中的强化应用到英雄

```json
// 请求
{ "hero": { ... }, "upgrade": { "id": "might", "add_attack": 6, ... } }
// 响应
{ "hero": { ... 已强化并裁剪到合法范围的英雄 } }
```
